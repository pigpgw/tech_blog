# 작업 계획 제목

## 목적

- 이 계획으로 해결하려는 문제와 사용자가 얻는 결과를 적는다.

## 배경

- 현재 상태, 관련 결정, 제약 조건을 적는다.
- 참고한 Skill, 문서, 코드 위치가 있으면 함께 적는다.

## 변경 범위

- 이번 작업에서 실제로 바꿀 범위를 적는다.
- 코드, 설정, 문서, UI, 데이터 타입, 라우팅처럼 영향을 받는 영역을 구분한다.

## 제외 범위

- 이번 작업에서 일부러 하지 않을 일을 적는다.
- 후속 작업으로 분리할 내용이 있으면 명확히 남긴다.

## 수정 파일 후보

- `path/to/file`: 수정 이유를 적는다.

## 단계별 작업

1. 현재 코드와 문서를 확인한다.
2. 필요한 타입, 함수, UI, 문서 변경을 최소 범위로 적용한다.
3. 관련 검증을 실행한다.
4. 실행 결과와 미실행 항목을 보고한다.

## 검증 방법

- `npm run type-check`
- `npm run lint`
- `npm run format:check`
- `npm run build`

## 미해결 질문

- 계획 승인 전에 결정해야 할 질문을 적는다.
- 없으면 `없음`이라고 적는다.
